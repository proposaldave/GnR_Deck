Use Local mode on main.

PUBLISH CONTRACT
- Do not edit deck content except conflict resolutions explicitly approved by Dave.
- Do not reset --hard.
- Do not force push.
- Do not delete branches or files.
- Do not manually resolve broad conflicts in a publish pass.
- Do not silently skip branches.
- Publish only verified branches.
- Do not claim all work is live unless every requested branch merged and verified.
- Protect `SLIDE_ORDER` as the active-slide inventory. A publish pass may not remove an active slide unless Dave explicitly requested that exact slide to be deleted, trashed, moved to appendix, or moved to an alt rail.
- Unauthorized active-slide removal is a hard publish blocker.

START CHECKS
- Run git branch --show-current, git status --short, git remote -v, git log --oneline --decorate -20, and git worktree list.
- Run `tools/audit_deck_publish_candidates.ps1 -BaseRef origin/main -CsvPath "$env:TEMP\gnr_publish_audit_unpublished.csv"` before making publish decisions.
- Treat the audit CSV as the required publish ledger for this run. Every row where `ContainedInBase=False` must end as merged, ported, already live, conflict, not verified, risky/delete/trash blocked, unrelated, or dirty worktree blocked.
- The audit output includes `PUBLISH_NOW_CANDIDATES`, `PORT_OR_CONFLICT_REVIEW`, `RISKY_OR_DELETE_BLOCKED`, `DIRTY_WORKTREE_BLOCKED`, and `BROKEN_REF_OR_MERGE_BASE`. These are publish-control gates, not status decoration.
- Confirm local HEAD, origin/main, and remote main.
- If main is dirty, identify every dirty file.
- If dirty work is unrelated, preserve it on preserve/[file-purpose]-local-change before cleaning main.
- Never discard dirty work.

BRANCH UNIVERSE
- Worktree list is not enough. A completed Codex session may leave a local deck/* branch that is not currently checked out.
- Build the publish candidate universe from the union of:
  checked-out deck/* branches from `git worktree list --porcelain`
  every local ref from `git for-each-ref refs/heads/deck --sort=-committerdate`
  every local deck/* branch not contained in origin/main
  recent deck/* branches with commit messages that look like completed deck edits
- For every local deck/* branch, run `git merge-base --is-ancestor <branch> origin/main`.
- If that returns false, the branch is an unpublished candidate until it is merged, ported, or explicitly blocked.
- Do not manually maintain the candidate list from memory. Use `tools/audit_deck_publish_candidates.ps1` as the mechanical source of the branch universe, then add human judgment for classification.
- Do not rely on the app status dot, worktree existence, branch name, or merge status alone.
- Before DONE, the count of clean or non-checked-out local deck/* branches not contained in origin/main must be zero unless each remaining branch is listed under BLOCKED / CONFLICTS / NOT VERIFIED with evidence.
- Report the exact unpublished-branch audit lines, including `UNPUBLISHED_LOCAL_DECK_REFS=N` and `PUBLISH_NOW_CANDIDATES=N`.
- Hard gate: do not report `DONE` while `PUBLISH_NOW_CANDIDATES` is greater than zero. Merge those branches before final output.
- Hard gate: do not report `DONE` while any `PORT_OR_CONFLICT_REVIEW` branch has not received a branch-specific intent extraction attempt. For each one, either port its tiny visible intent, or list the exact selector/text/registry conflict that prevents safe porting.
- If `UNPUBLISHED_LOCAL_DECK_REFS` is not zero at the final audit, the run may finish only when every remaining branch name from the audit appears in a persistent unresolved ledger and in the final report bucket summary with exact state and next action.
- The final state must prove `ZERO_SAFE_OR_PORTABLE_LEFT=True`, meaning there are no remaining `publish_now` branches and no unexamined `port_or_conflict_review` branches.

PUBLISH QUEUE GATE
- This is an integration loop, not a one-pass summary.
- Process branches in this order:
  1. `publish_now`: direct merge, verify, mirror, and later push.
  2. `port_or_conflict_review`: inspect diff from merge-base; if the visible intent is small and clear, port it surgically, verify, then mark the branch integrated with `ours`; if not clear, record exact blocker.
  3. `risky_clean_needs_review` and `risky_conflict_blocked`: block unless Dave explicitly requested the exact delete/trash/slide-order action in the current publish request or the branch commit body contains explicit authorization for the removed active slide IDs.
  4. `dirty_worktree_blocked` and `broken_ref_or_merge_base`: block with exact branch/path/ref reason.
- Do not leave a `publish_now` branch behind because there are many branches.
- Do not leave a tiny copy/CSS/asset/registry intent behind just because direct merge conflicts. Port it if the intent is unambiguous and active-source safe.
- Create or update `publish_audit_unpublished.csv` only as a local audit artifact unless Dave explicitly asks to commit it.

FAILED-EDIT PHRASE TRACE
- If Dave names old visible text, new visible text, a screenshot, or says "didn't I ask you to change/move/delete this", do not rely on branch names.
- Search current `GnR_deck.html`, `index.html`, raw GitHub, and Pages source for the visible text.
- Search every local deck/* branch content and diff for the exact phrase and nearby slide ID:
  `git grep -n -i "<visible phrase>" <branch> -- GnR_deck.html`
  `git diff $(git merge-base main <branch>) <branch> -- GnR_deck.html`
- A branch that contains the requested replacement or removes the old phrase is a publish candidate even if it is not checked out and even if the branch name does not mention the phrase.
- If the intent is a tiny copy/layout/registry change, port it to current main, verify old text absent/new text present in the exact active selector/DOM line, then mark the source branch integrated.
- Do not pass failed-edit verification by finding the replacement elsewhere in the same slide, a top-left eyebrow, an alt, a hidden duplicate, a comment, an appendix block, or an inactive retained block.
- If the old visible text remains in the original active selector/DOM line, the edit is not live, even if the replacement appears somewhere else.

BRANCH INVENTORY
- List all local deck/* branches.
- Classify each as already merged, safe candidate, conflict, risky/delete/trash, likely inactive-variant edit, unrelated, broken ref, or unknown.
- Treat completed Codex worktree sessions shown by a solid status dot in the app UI as publish candidates.
- Do not make Dave identify completed branches manually. Resolve the likely matching deck/* branch from the session/task name, worktree list, branch name, and commit message.
- Before reporting DONE, audit remaining checked-out deck/* worktrees, non-checked-out local deck/* branches, and recent deck/* branches against main and origin/main. No completed-session branch may disappear into a generic skipped bucket.
- For each completed-session branch, do one of three things: merge it cleanly, port the requested intent onto current main when a direct merge would roll back newer live work, or report BLOCKED with the exact conflict/risk and next action.
- For every branch not published, report the branch and the blocker. Do not use "skipped" as a final state for completed work unless the blocker is explicit and actionable.
- For every completed-session branch, inspect the branch diff from its merge-base, not just branch name or merge status. Extract the visible text, slide IDs, CSS selectors, JS functions, assets, and registry entries it intended to change.
- For visible text changes, extract the exact selector/DOM line that rendered the old visible text before the branch and verify that same active selector/DOM line after merge/port.
- Do not mark a branch integrated with an `ours` merge until the branch intent is verified in current main/source/render. If the intent is missing, port it first, verify it, then record integration.
- If a branch is already an ancestor of main but the visible requested result is absent, treat it as a failed publish and repair/port the intent before DONE.
- If a branch is not checked out but is a local deck/* branch not contained in origin/main, inspect it exactly like a checked-out worktree branch.
- If a branch is stale and a direct merge would remove newer live work, do not skip it. Port only its visible intent to current main, verify the active source/render result, then mark the branch integrated with an `ours` merge.
- If a branch intent is small and mechanical, such as CSS position, copy, order, or registry changes, do not leave it unpublished because the branch is stale. Port the tiny intent and verify it.
- If a branch requested multiple visible edits, all visible intents must be merged or ported before marking the branch integrated. Partial branch integration is a publish failure unless the unported part is listed under BLOCKED with the exact reason.
- Prefer branches whose final report or commit evidence indicates active-slide verification.
- Do not publish branches that appear to edit inactive variants without active-source/render verification; either port the intent to the active source when obvious or report BLOCKED.
- Do not blindly merge delete/trash/risky branches; if Dave clearly requested that finished branch, apply the deletion/trash intent surgically to current main or report BLOCKED.
- For any branch or port that changes `SLIDE_ORDER`, compare before/after active slide IDs. Report `ADDED_SLIDES` and `REMOVED_SLIDES`. Every removed ID must have explicit request evidence from Dave's task or the branch final report.
- If a completed branch direct merge would remove unrelated active slides, do not direct merge it. Port only the requested intent and preserve all unrelated active slide IDs.
- If adding, restoring, deleting, or moving a main-flow slide shifts later positions, update the affected `SLIDE_ALTS` keys so existing alt rails stay attached to the intended active slide.
- Do not manually resolve broad conflicts. For a completed branch with a small clear intent, port the intent surgically; otherwise report CONFLICTS with the exact branch.
- Merge only verified safe completed deck/* branches Dave asked to publish or clearly approved.
- If a branch conflicts, abort that merge and list it under CONFLICTS. Do not fix it unless Dave asked for that branch specifically.

PUBLISH-READINESS EVIDENCE
- Prefer a commit body or branch final report containing PUBLISH TRACE / INTEGRATION NOTE.
- If the branch has no publish-readable final report, infer intent from:
  commit message
  `git log -1 --format=%B <branch>`
  `git diff $(git merge-base main <branch>) <branch> -- GnR_deck.html`
  changed selectors, visible text, slide IDs, registry keys, JS functions, and assets
  active-source presence in current main
- For every published branch, verify the branch intent in current main after merge or port. For visual/layout changes, verify the exact selector/property or rendered visible result.
- For copy changes, verify the exact active selector/DOM line changed. `new text exists somewhere` is not sufficient. `old text still exists in the original active selector` is a failed publish.
- For every completed clean branch without PUBLISH TRACE, record `MISSING_PUBLISH_TRACE` in the report but do not use that alone as a reason to skip it. Infer and verify the visible intent yourself.
- For every branch marked integrated with `ours`, include `OURS_AFTER_INTENT_VERIFIED` and name the verified text/selector/registry marker. Never use `ours` as a shortcut to make an unresolved branch disappear.
- For every branch that remains unresolved, record a one-line ledger entry:
  branch | bucket | mergeability | worktree status | exact blocker | exact next action
- The unresolved ledger is the handoff for the next publish pass. Do not rely on Dave to re-identify these branches from screenshots.
